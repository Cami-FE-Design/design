## Sales, ledger, and entitlement

> Incorporated from Michelle's sales-domain glossary (Slite draft, 2026-07-31). Canonical for the sales/ledger domain. "Do not use" lists the wrong synonyms. Note: **Balance** has two senses, the payments-domain "remainder due after a deposit" (above) and the stored-value sense below (gift-card value derived from the ledger); disambiguate in context.

| Term | Definition | Do not use |
|------|-----------|-----------|
| **Line item** | One sellable unit on an invoice: a service, product, package, membership, or gift card. | item, row |
| **Tender** | The method that satisfies an invoice: card, cash, gift card, package session, membership benefit. | payment type |
| **Capture** | The moment payment is confirmed and entitlements commit (see INV-07). | charge, process |
| **Settlement** | End-of-day batch where captured payments move to the merchant account. | payout |
| **Credit note** | The financial document issued when a completed sale is refunded. | refund receipt |
| **Cancel** | Applies to appointments only, never to invoices. An appointment can be cancelled before it happens. | (avoid for financial objects) |
| **Restock** | Returning refunded product quantity to inventory. Optional on refund, automatic on void. | return to stock, re-add |
| **Clawback** | Recovering discount value when a customer exits a bundle early (see ADR-019 / PDR-001). | penalty, forfeit |
| **Archive** | Removes an item from sale while preserving history and issued entitlements. The default meaning of "remove" in Settings (INV-02). | delete, deactivate, disable |
| **Delete** | Permanent removal. Only for items never transacted against. | (avoid in UI copy) |
| **Discontinued** | UI state for an archived item that still has live entitlements outstanding. | inactive |
| **Ledger** | The append-only event list a balance is derived from (INV-03). | history, log |
| **Balance (stored value)** | Derived value of a gift card at a point in time, computed from the ledger, never stored (INV-03). | amount, remaining |
| **Hold** | A reservation against a balance or entitlement, placed at intent, released on abandonment (INV-07). | lock, reserve |
| **Package** | A prepaid entitlement to specific services in specific quantities. Finite, consumed by redemption. | bundle, deal |
| **Membership** | A recurring or fixed-term entitlement conferring ongoing benefits (discounts, included services). | subscription, plan |
| **Session** | One unit of package entitlement, consumed by one covered service line item ("3 sessions of Full Groom"). See ADR-020 / PDR-002. | credit, visit, use |
| **Redemption** | The act of consuming one session against one service line item. | usage, consumption |
| **Entitlement list** | A package's structure: service ID + quantity, repeated. The Cami package model (ADR-020). | contents |
| **Value wallet** | Alternative package model holding currency value rather than sessions. Not in MVP. | store credit |
| **Service** | Labour sold by time (groom, treatment, consultation). | treatment |
| **Product** | Physical goods sold from inventory. Stock-tracked. | retail, item |
| **Invariant** | A platform-wide rule holding across all modules. Prefix `INV-`. | |
| **Rule** | A module-specific business rule in testable Given/When/Then form, prefixed by module (e.g. `PKG-06`). | |
| **PDR** | Product Decision Record; documents a choice where a real alternative was rejected. Prefix `PDR-` (mapped to the ADR series here). | |
| **DRI** | Directly Responsible Individual. Exactly one per artifact and per decision. | |
| **Payment policy** | The owner's config for when clients must pay (deposit / prepay, refundable-until, reschedule window, auto-cancel) and which methods appear. Business-level for pilot; resolved booking → service → business (INV-13). Checkout consumes it, does not invent it. | |
| **Promotion** | An owner-configured discount that reduces the payable total, with scope, validity window, minimum purchase, and status. At most one per line (INV-13). Distinct from the ad-hoc cart discount. | promo, deal, coupon |
| **Prepay** | An optional pay-in-full at booking, offered independently of the deposit policy. | |
| **Cart draft** | An unfinished cart saved before checkout. **Not a sale**: no sale number, not in the Sales list, no payment status; reopens into checkout. Distinct from a **draft sale** (created when a payment link is generated). | |
| **Walk-in** | A sale with no attached client; the client can be added/changed/removed any time before payment. Always allowed. | anonymous |
| **Refund document** | The separate, negatively-signed record a refund creates above the original sale. The original stays visible and `Completed`. | |
| **Refunded-to-date** | The running total refunded against a sale. The sale stays `Completed` (no "partially refunded" status) and shows this plus still-refundable. | |
| **Change due** | Cash tendered above the balance. Settles the sale in full; not a payment line, does not increase collected. | |

## Money composition

> Canonical for how money objects combine on one invoice. Full definitions and the rules themselves live in [06 Money Composition Contract](06-money-composition-contract.md). Note a **third** sense of "Balance" is not introduced here: **amount due** is the figure the customer pays, use that term, not "balance" or "total".

| Term | Definition | Do not use |
|------|-----------|-----------|
| **Money Composition Contract** | The binding doc (06) defining how money objects compose onto one invoice. Contract, not model: a violation is a defect, and a failing INV-M is a release blocker. Distinct from a merchant agreement or a provider agreement, which are commercial contracts. | money model, money contract, payments contract |
| **Composition Order** | The fixed 10-step sequence money objects apply in (06 §2): line price → line discount → package redemption → cart discount → pro-rata allocation → VAT derivation → taxable gross → tip → amount due → tender. Cited by step number. | waterfall, pipeline, money flow, totals order |
| **Scope Rule** | The rule (06 §3) stating whether an object is invoice-scoped (mutates balance, persisted on the invoice) or payment-scoped (tender record only). Tip is invoice-scoped. | scope table |
| **Line price** | Price of a single service or product as the merchant configured it. Stored VAT-inclusive. | unit price, base price |
| **Line gross** | A line's amount after discounts and redemptions apply to it. `line_gross_final` is its value at the end of the Composition Order. | line total, line amount |
| **Line discount** | A reduction applied to one specific line. Reduces taxable gross. | line-level promo |
| **Cart discount** | An ad-hoc reduction applied across eligible lines, allocated back pro-rata. Reduces taxable gross. Distinct from a **Promotion** (owner-configured, at most one per line). | order discount, global discount |
| **Taxable gross** | Sum of `line_gross_final` across all lines, VAT-inclusive. The base VAT is derived from. **Not** the figure the customer pays whenever a tip exists. | subtotal, net |
| **Amount due** | Taxable gross + tip. The figure the customer pays. Reported separately from taxable gross at all times. | total, grand total, balance |
| **Package redemption** | Drawdown against a sold package entitlement, rendering the line at zero gross. Neither a discount nor a tender. Redeemed lines are not cart-discount-eligible. | package discount, package payment |
| **Tip** | Voluntary gratuity, staff-entered at checkout, invoice-scoped, outside the VAT base. A **mandatory service charge** is a different object and is taxable, currently an open decision (06 §9.1). | gratuity, service charge |
| **Credit** | Merchant-issued balance arising from a refund or adjustment. A tender. | store credit, account balance |

## Reporting and analytics

> Incorporated from the #reports channel (Anum, Sham, Maaz, Faisal, Jul–Aug 2026). Reporting architecture is in design, not finalized; terms below are canonical for the domain.

| Term | Definition | Do not use |
|------|-----------|-----------|
| **Reports module** | Cami's reporting surface, two report types: **table-format** CSV/Excel downloads (finance/compliance) and **analytics-dashboard** views (flexible datapoints). Scope is POS + booking analytics, not full accounting. | |
| **Table-format report** | A downloadable CSV/Excel report locked to the Michelle/Linear designs. The ship-now tier (sales log detailed, payments log, tips collected). | |
| **Analytics dashboard** | A visual dashboard view with flexible datapoints per dashboard, Fresha-derived, optimized from Sham + customer feedback. Shipping as v2. | |
| **Partner Dashboard (CamiHQ BI)** | The cross-merchant, portfolio-level reporting view for internal CamiHQ use (Account Managers), like Fresha's Periscope/Sisense dashboard. Built on the same reporting pipeline as merchant reports, not retrofitted. | |
| **Fact table** | An event-grain reporting table (one row per event, e.g. a sale line or appointment), the persisted store the reports read from. Distinct from the OLTP source tables. | |
| **Event-grain** | Stored at the level of individual events/line items, not pre-aggregated totals. Lets formulas recalculate over history without schema change. | |
| **Redis cache (reporting)** | Short-lived cache entries for low-latency embedded reports. **Not** persisted aggregates; the "precomputed summaries" in early docs are cache, not stored rollups. | |
| **Transactional outbox** | The reliability pattern replacing the in-process event emitter (which can lose an event between OLTP commit and queue publish). Covers replay, backfill, idempotency, dead-letter. | |
| **Gift card breakage** | Unused gift-card balance that expires and converts to recognized revenue. **Not tracked today** (income gap). | |
| **Occupancy %** | Staff booked hours ÷ staff scheduled hours (booked = booked − cancelled; scheduled = scheduled − breaks). | utilization |
| **Returning client rate** | Returning clients ÷ all clients seen. Definition of "returning" still open. | |
