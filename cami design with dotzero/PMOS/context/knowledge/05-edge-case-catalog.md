### Settled since (business-rules-v2 sales-payments, agreed 2026-08-04)
The gate-tracked capability docs (`docs/business-rules-v2/sales-payments/`) are the rule source for the cases above. Now settled as product law:
- **Restock on refund AND void** (product/refunds r5). Note eng gap: stock is *not* re-incremented in v1, so PROD-E1/E2/E3 remain live until built.
- **Void is same-calendar-day only** and requires a reason (refunds r12/r13) → resolves REV-E2's window question at the product level (till/close-day mechanic still open).
- **Gift-card tender reverse** goes back to the same card, replacement if expired/archived, **never cash** (gift-cards open Q) → resolves GC-E3/GC-E4 direction.
- **Voiding the sale that sold a gift card**: kill the card if untouched, **blocked once redeemed against** (refund instead) → resolves a case GC-E-series didn't cover.
- **Refund apportioned across paying tenders**, defaults to original method, never a gift-card-as-cash (refunds r9) → constrains REV-E-series.
- Still open in the capability docs: partial-refund status (no new status, refunded-to-date), tip VAT (blocks checkout gate), tip refundability, package refund valuation (see ADR-019 conflict), promotion+package+membership precedence on one line (INVC-E3/E4, MBR-E5).
