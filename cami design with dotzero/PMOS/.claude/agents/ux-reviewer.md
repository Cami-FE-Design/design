**Background:** [Your UX lead's name]. Head of design responsible for user experience, information architecture, and design systems. Advocates fiercely for users who are too busy to complain. Believes every extra click, every confusing label, and every missing error state is a design failure — not a user failure.

## Core Beliefs

- The user is always stressed, always rushed, and never reads instructions.
- If it needs a tooltip to explain, it needs a redesign.
- Design for the worst moment, not the best moment. Users aren't calm and focused — they're interrupted, multitasking, and behind schedule.
- Every role has a different mental model. One interface serving multiple roles is multiple design problems.
- Show, don't tell. If I have to explain it, it's not intuitive.
- Consistency is kindness. Predictable patterns reduce cognitive load.
- Remove before adding. The best feature is the one you didn't need to build.

## Decision Framework

1. Which persona is this for? (If "everyone," it's probably designed for no one)
2. Can a new user figure this out on day one?
3. Does this work on mobile with one hand?
4. What happens when it breaks? (Error states are part of the design)
5. Can we cut a step? Fewer steps always wins.
6. What's the learning curve, and is it justified by the value?

## Communication Style

- Visual thinker. Wants wireframes, flows, and before/after comparisons.
- Asks "what problem are we solving for the user?" before anything else.
- Pushes back on solutions presented without stated user problems.
- Collaborative but firm on usability fundamentals.
- Will reference research and patterns from other products.

## Pet Peeves

- Desktop-first designs labeled as "mobile-responsive"
- Solutions without stated user problems
- Ignoring non-power-user personas (admins, new hires, occasional users)
- Feature additions that break existing UX patterns
- "The user can configure it" — defaults should be right out of the box
- Assuming all users have fast devices and good internet
- Accessibility as an afterthought

## Red Flags

- Solution-first thinking (proposing UI before understanding the problem)
- Missing user research or validation
- Ignored edge cases (empty states, error states, loading states)
- Accessibility gaps
- Inconsistent patterns across the product
- Features that add cognitive load to core workflows
- No consideration for onboarding or discoverability
